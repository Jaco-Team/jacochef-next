# Сценарии тестирования Управления кафе

План для frontend-модуля `cafe_edit`, сверенный с кодом 27.11.2026. Он сохраняет ранее составленный список сценариев: загрузка кафе, права, создание, реквизиты, разгрузка, несохранённые изменения, коэффициенты и зарплата, настройки, курьеры, закрытие, зоны, кассы, ФН, история и повторное открытие диалогов.

Это список будущих unit- и компонентных тестов, а не отчёт о полном покрытии. Код приложения в рамках подготовки плана не меняется. Обнаруженные по чтению кода расхождения сначала воспроизводятся тестом; исправления приложения согласуются отдельно.

## Приоритеты, уровни и статусы

- **P0** — права, сохранение, валидация, потеря или подмена данных. **P1** — дополнительные состояния, представление и повторное открытие.
- **Unit** — только существующие экспортируемые store и helper-функции. **RTL** — настоящий компонент, его обработчики и дочерние формы в Vitest/jsdom.
- **Покрыто** — указан существующий тест именно этого поведения. **Частично** — есть общая инфраструктурная проверка, но сценарий модуля целиком не проверен. **Запланировано** — прикладной тест ещё предстоит написать.

Сейчас в `tests/vitest/components/infrastructure/cafe-modal.test.jsx` есть три теста: запрет сохранения без города; проверка адреса и вызов callback с введёнными данными; очистка DOM, браузерных хранилищ и обоих store. Проверки `tests/vitest/unit/infrastructure/access.test.js` исполняют общую политику прав, но не доказывают правильность всех вкладок и обработчиков кафе. Общие network-тесты проверяют подмену запросов, а не каждый метод `cafe_edit`.

## Как реализовывать

Сначала P0: создание и реквизиты, права, выбор кафе, сохранение и отмена. Затем настройки/закрытие, зоны, кассы/ФН; после этого история и остальные P1.

Рендерить настоящие компоненты через `tests/vitest/render.jsx`, задавать реальные значения прав и состояние store. Inline-обработчики `CafeEdit.jsx` проверять через UI и MSW; ради теста не извлекать их из исходника через регулярные выражения/VM и не выносить в новые функции приложения. Для Unit использовать существующие экспортируемые store и policy/helper.

Подменять HTTP на `http://chef.test/api/cafe_edit/*` и внешнюю границу Яндекс.Карт. Фикстуры должны повторять envelope API, ожидаемый `api_laravel` и `getData`, включая `acces`, `module_info`, `points`, `point_info`, списки истории, зон и касс. Новые поля ответа не придумывать. Неподменённый запрос — ошибка теста. Для таймеров загрузки/сброса и сроков ФН фиксировать часы и завершать ожидаемые таймеры; после теста сбрасывать оба store.

Рекомендуемое место будущих файлов: `tests/vitest/components/cafe-edit/` и `tests/vitest/unit/cafe-edit/`. Пока они не созданы, scope `cafe-edit` не существует. Уже существующие три проверки диалога можно выполнить из корня проекта командой `npm run test:vitest -- --project=components tests/vitest/components/infrastructure/cafe-modal.test.jsx`. Полный unit-набор: `npm run test:unit`.

Реальные API/БД, выполнение закрытия кафе на сервере, проверка выдачи заказов курьерам и точная геометрия карты в этот план unit/RTL не входят. E2E сейчас не добавляются и не запускаются.
