# API журнала бактерицидных ламп

Backend-копия журнала ламп внутри Chef-модуля `Cleanings`. Старый standalone-модуль
и его маршруты остаются доступными и этим контрактом не изменяются.

Локальный API: `http://127.0.0.1:8000/api`.

Все запросы используют текущую авторизацию Chef и передают бизнес-поля в `data`.
Поле `data` может быть объектом или JSON-строкой.

## Маршруты

| Метод | Маршрут                          | Назначение                        |
| ----- | -------------------------------- | --------------------------------- |
| ANY   | `/cleanings/lamps/bootstrap`     | точки, метаданные и доступ        |
| ANY   | `/cleanings/lamps`               | лампы и активности за период      |
| ANY   | `/cleanings/lamps/history`       | история изменений одной лампы     |
| ANY   | `/cleanings/lamps/save`          | создание или изменение лампы      |
| ANY   | `/cleanings/lamps/activity/save` | создание или изменение активности |
| ANY   | `/cleanings/lamps/replace`       | замена лампы                      |
| ANY   | `/cleanings/lamps/export`        | экспорт XLS                       |

## Загрузка

`/cleanings/lamps` принимает:

```json
{
  "pointId": 1,
  "dateFrom": "2026-08",
  "dateTo": "2026-08"
}
```

Для переходного периода также поддерживаются `point_id`, `date_start` и
`date_end`. Даты передаются в формате `YYYY-MM`.

Успешный ответ сохраняет табличный контракт старого журнала:

- `list` — определения ламп и накопленное время `svod` в формате `H:MM`;
- `lamp_groups` — lifecycle-группы: текущая лампа в `active` и явно связанные
  заменённые версии в `inactive`; совпадение номера/модели/места не создаёт
  связь автоматически;
- `active_lamp` — строки по датам с менеджером и ячейками активностей;
- `st` — признак успешного ответа.

Каждая лампа в `list` также содержит стабильный `id`, порядковый номер `number`,
модель `name`, ресурс `resource`, накопленное за выбранный период время `svod`,
накопленное за всю историю лампы время `total_svod` и служебные даты
установки/снятия при наличии. Каждая строка `active_lamp` содержит `manager_id`
и отображаемое имя `manager`; ячейка активности содержит `shift_manager_id`,
`entered_by_user_id` и `updated_by_user_id`.
Если для даты нет записи менеджера смены, `manager_id`/`manager` используют
автора первой активности этой даты как технический fallback, чтобы подпись не
терялась в интерфейсе.

`/cleanings/lamps/history` принимает `pointId`, `lamp_id` и необязательный
`limit` (1–100). Ответ содержит `history` в стандартном формате `HistoryLog`.
В истории остаются только изменения лампы, замены и исправления активности;
обычная ежедневная запись активности отдельным событием истории не создаётся.
Для пользовательских полей история сохраняет идентификатор и имя в
`meta_json.user_fields`, а интерфейс показывает имя и ID вместе.

## Изменения

Для `/cleanings/lamps/save` обязательны `pointId`/`point_id`, `number`, `name`,
`resource`, `place`. Для изменения существующей лампы передаётся `id`.
У существующей версии номер и место нельзя менять через обычное редактирование;
они фиксируют позицию версии и меняются только при замене.

Для `/cleanings/lamps/activity/save` обязательны `pointId`/`point_id`, `lamp_id`,
`time_start`, `time_end`. Для изменения существующей активности передаётся `id`.
`active_sec` рассчитывается backend. Новая активность не создаётся для даты
старше вчерашней и при существующей записи этой лампы за тот же день.

Для `/cleanings/lamps/replace` передаются `pointId`/`point_id`, `lamp_id` и
обязательная непустая `replacement_reason` (например, `Неисправна`,
`Повреждена`, `Выработан ресурс` или `Плановая замена`).
Старая лампа деактивируется, получает `removed_at` и `replaced_by_lamp_id`, а
новая запись с теми же номером, местом, моделью и ресурсом создаётся
транзакционно с новым ID. Старые активности не переносятся.

## Ошибки и доступ

```json
{
  "st": false,
  "text": "Сообщение ошибки"
}
```

Маршруты относятся к `Cleanings`. Для журнала используются два параметра
доступа в категории `Журнал замены бактерицидных ламп`:

- `lamps` — видимость раздела и CRUD журнала;
- `lamps_export_excel` — экспорт XLS.

Значения перенесены из старого модуля: видимость раздела сохранена для тех же
шести ролей, экспорт — для тех же трёх ролей. Новые записи можно создать или
откатить командой backend `cleanings:migrate-lamp-access`.

## Локальная проверка

Backend проверен на локальной MariaDB из конфигурации `127.0.0.1:3307`.
Таблицы `lamps` и `lamps_active`, а также данные присутствуют во всех настроенных
point-base схемах. Production import для текущей локальной базы не потребовался.

Этот документ описывает API и не заменяет пользовательскую документацию.
