# Трассировка покрытия ТЗ

Статус относится к исходному коду текущей ветки. «Частично» означает, что есть часть контракта или UI, но нет полного сквозного подтверждения на локальных данных. ТЗ остаётся критерием приёмки; более подробные шаги и критерии находятся в [PLAN.md](./PLAN.md).

| Пункт ТЗ | Целевой процесс                                            | Текущий статус                | Что остаётся                                                        |
| -------- | ---------------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------- |
| 1–2      | Регистрация жалобы, состав, несколько ошибок и единый путь | Частично                      | Сквозно сохранить ошибку блюда, две ошибки позиции и ошибку заказа. |
| 3–4      | Аудит настроек и жалобы                                    | Частично                      | Проверить создание, изменение и маршрутизацию на локальном API.     |
| 5        | Единая терминология классификатора                         | Частично                      | Применить к журналу, деталям и статистике.                          |
| 6        | Настройки по кафе: дерево, активность, история             | Реализовано по исходному коду | Проверить область кафе, права и сохранение.                         |
| 7        | Автоклассификация объекта заказа                           | Реализовано по исходному коду | Проверить все типы объектов на локальных данных.                    |
| 8        | Удаление режима описания                                   | Реализовано по исходному коду | Проверить смежные поверхности.                                      |
| 9        | Очистка «Контакт-центр нов»                                | Не проверено                  | Найти фактическую интеграцию и удалить только связанные элементы.   |
| 10–11    | Полный журнал и детали заказа                              | Не реализовано                | Создать read-model, серверные фильтры, сортировку и пагинацию.      |
| 12       | Раздельная статистика КК/кафе                              | Частично                      | Проверить расчёты и фильтры на фикстурах.                           |
| 13       | Рассмотрение жалобы кафе                                   | Частично                      | Добавить frontend-действия, роли и правило удержания.               |
| 14–15    | Этапы и решения                                            | Реализовано по исходному коду | Проверить сохранение, активность и аудит.                           |

Задача не может быть закрыта только по наличию экранов: требуется локальная цепочка «заказ → регистрация → рассмотрение → аудит → журнал → статистика».
