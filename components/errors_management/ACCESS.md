# Матрица доступа модуля «Регистрация ошибок»

## Принципы

Доступ к данным жалобы определяется разрешёнными кафе пользователя через `Helper::getMyPointList` и `Helper::userHasPointAccess`. Клиент не является источником истины для кафе, статуса или доступного действия: каждое чтение детали, создание и переход проверяются на backend.

`source` — канал регистрации жалобы, а не право доступа. Роль определяет доступное действие, доступ к кафе ограничивает область данных.

## Вход в модуль

v2 routes находятся только за общим token middleware. Сейчас backend не проверяет отдельный capability входа в модуль: любой аутентифицированный пользователь с доступом к кафе проходит чтение и регистрацию. Legacy-флаги `err_order_mod_access` и `tel_access` в v2 не участвуют. До приёмки владелец процесса должен подтвердить отдельный capability входа либо явно принять текущую модель доступа по кафе.

## Роли и рабочий процесс

| Роль приложения                  | Канал новой жалобы | Доступные действия                                                    | Область кафе                                                              |
| -------------------------------- | ------------------ | --------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Контакт-центр и иные некафе-роли | Контакт-центр      | Зарегистрировать; для своей новой жалобы отправить в кафе             | Только кафе из разрешённого списка                                        |
| `manager`                        | Кафе               | Зарегистрировать; принять отправленную жалобу; завершить рассмотрение | Только свои кафе                                                          |
| `dir`, `dir_other`               | Кафе               | То же, что менеджер                                                   | Только кафе из разрешённого списка                                        |
| `mega_dir`, `MEGA`               | Кафе               | То же, что менеджер                                                   | Региональный или расширенный набор кафе, который возвращает legacy helper |

Кафе-роль, зарегистрировавшая жалобу, сразу переводит её в рассмотрение кафе. Контакт-центр не может повторно отправить такую старую запись в то же кафе. Роль не заменяет проверку кафе: менеджер без доступа к конкретной точке не читает и не меняет её жалобы.

## Карта endpoint-ов

| Endpoint              | Чтение/изменение               | Обязательная проверка                                                                                                                       |
| --------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `v2/context`          | Контекст регистрации заказа    | Доступ к переданному кафе                                                                                                                   |
| `v2/create`           | Создание жалобы                | Доступ к кафе; серверная валидация заказа, позиций, каталога и этапа                                                                        |
| `v2/journal`          | Журнал                         | Только `allowedPoints`; фильтр конкретного кафе дополнительно проверяется                                                                   |
| `v2/statistics`       | Статистика                     | Только `allowedPoints`; фильтр конкретного кафе дополнительно проверяется                                                                   |
| `v2/detail`           | Детали и доступные действия    | Доступ к переданному кафе и совпадение кафе жалобы                                                                                          |
| `v2/transition`       | Отправка, принятие, завершение | Доступ к кафе; допустимость команды для роли и статуса; optimistic lock                                                                     |
| `v2/settings`         | Чтение каталога                | Глобальный каталог доступен для чтения; точечный каталог должен быть ограничен доступом к кафе                                              |
| `v2/settings/save`    | Создание и изменение настройки | Capability `errors_management_settings_edit`; для точечной настройки доступ проверяется и по сохранённому кафе, и по кафе из нового payload |
| `v2/settings/history` | Аудит настройки                | Доступ к области настройки должен проверяться до выдачи истории                                                                             |

## Legacy-границы

Старые флаги `tel_access` и `err_order_mod_access` описывают legacy-экран. v2 endpoint-ы их не читают и не используют как fallback. Это исключает скрытое расширение прав через старую форму, но миграция матрицы module access должна быть подтверждена отдельно.

## Проверка перед приёмкой

- Пользователь без доступа к кафе получает отказ для контекста, создания, деталей, перехода и фильтров журнала/статистики.
- Менеджер, управляющий и региональный директор видят только набор кафе legacy helper и могут принять/завершить жалобу только в нём.
- Контакт-центр может отправить только допустимую жалобу; кафе-источник не отправляется в то же кафе повторно.
- Capability без доступа к выбранному кафе не позволяет изменить точечную настройку.
- Подтверждён отдельный capability входа в модуль либо зафиксировано, что доступа к кафе достаточно.
- История и сам каталог точечной настройки не раскрывают данные чужого кафе.
