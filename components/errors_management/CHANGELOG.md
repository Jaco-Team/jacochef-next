# История изменений модуля «Регистрация ошибок»

## 2026-09-30 — настройки вариантов решения жалоб

- Добавлена вкладка «Варианты решения жалоб» на v2-каталоге вместо пустой заглушки.
- Реализован фиксированный порядок разделов: «Блюдо», «Заказ», «Допы», «Столовые приборы», «Доставка».
- Добавлено управление типами ошибок, ошибками, этапами и решениями: создание, редактирование, порядок, активность и аудит.
- Ошибка может явно требовать выбор продукта из состава блюда; это правило передаётся в форму регистрации.
- Активные элементы показаны в рабочих разделах, неактивные сохранены в отдельной свёрнутой группе.
- Настройки вынесены из страницы в самостоятельный раздел; редактор ошибки регистрации также вынесен из контейнера страницы.

Сквозная проверка команд сохранения, аудита и регистрации остаётся незавершённой, пока локальный API `127.0.0.1:8000` недоступен.

## 2026-10-01 — журнал, детали и поиск

- Журнал получает серверную проекцию заказа пакетно по кафе: клиент, адрес доставки, сумма заказа и способ оплаты; добавлены общий комментарий, решивший сотрудник, статус, суммы ошибки и изменения.
- Детали жалобы показывают источник оформления заказа, сотрудника, комментарий клиента и промокод заказа при наличии. Источник сайта определяется связью `orders.client_id → site_users.id`.
- Аудит жалобы оформлен отдельными карточками событий со статусами маршрута и изменёнными значениями.
- Поле серверного поиска заказа приведено к числовому MUI-полю с обычной плавающей меткой. Табличный `JacoSearch` исправлен: его черновое значение не теряется до debounce и он не показывается без строк.
- Добавлены проверка этапа на уровне ошибки и проверка доступных переходов по роли; unit-набор модуля проходит локально.

Поля выписанных и активированных промокодов пока не добавлены в журнал: для активированного промокода отсутствует подтверждённый v2-контракт, поэтому значение не имитируется из legacy-данных.
