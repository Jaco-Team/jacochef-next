# Текущий рефакторинг: «Регистрация ошибок»

Документ фиксирует дефекты, найденные при UI-обходе 02.10.2026, и порядок их устранения. Критерий приёмки — ТЗ v1.02, `TARGET_BP.md` и `PLAN.md`; этот файл не расширяет ТЗ, а только перечисляет расхождения и технический долг.

## Безопасность проверки

- Frontend: `next dev` (`NODE_ENV=development`) на `localhost:3000`, `NEXT_PUBLIC_API_URL=http://127.0.0.1:8000/api` из `.env.development`.
- Все запросы модуля во время обхода ушли только на `127.0.0.1:8000`: `get_all`, `header/get_all`, `get_orders`, `v2/journal`, `v2/detail`, `v2/context`, `v2/statistics`, `v2/settings`, `v2/settings/history`.
- Backend: локальный `test-app-site` (`APP_ENV=local`, PHP слушает только `127.0.0.1:8000`), подключение `mysql_jaco_main_rolls` → `DB_HOST=127.0.0.1`.
- Пишущие endpoint-ы (`v2/create`, `v2/transition`, `v2/settings/save`) не вызывались; формы открывались без сохранения.
- Риск: `api_laravel` при пустом `NEXT_PUBLIC_API_URL` падает на прод `https://apichef2.jacochef.ru/api`. Без `.env.development` локальный запуск ходит в прод. Перед любыми пишущими проверками убедиться, что переменная задана.

## Порядок работ

1. Загрузка и пустые состояния (1, 21, 36): без этого остальные проверки дают ложные выводы.
2. Различимость жалоб и полнота данных (13, 14, 17, 18, 22, 23): требования ТЗ.
3. Валидация и черновик регистрации (24, 25, 26).
4. Декомпозиция `ErrorsManagement.jsx` (34) и удаление мёртвого кода (35) — отдельными `refactor:` коммитами без изменения поведения.
5. Фильтры и адаптив (7–12, 15, 32, 33).
6. Полировка (2–6, 16, 19, 20, 27–31).
