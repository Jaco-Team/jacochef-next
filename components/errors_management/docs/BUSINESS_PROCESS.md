# Бизнес-процесс

## Регистрация

1. Сотрудник выбирает город и кафе (или «Все точки в городе») и находит заказ: период по умолчанию — сегодня, есть фильтр по времени суток. Номер заказа из одних цифр ищется точно и без периода; любой другой поиск идёт в пределах периода.
2. Регистрация получает позиции заказа с категорией сайта и типом товара (`rolls`, `pizza`, `drinks_extras`), дерево категорий, этапы и решения.
3. Для позиции добавляется любое число ошибок; ошибки всего заказа добавляются отдельно.
4. Ошибка выбирается каскадом по дереву /option_to_win от корня до активного листа любой глубины:
   - позиции с категорией сайта — ветки, в пути которых есть эта категория (для категории 7 — «Столовые приборы» и «Допы», корень выбирает сотрудник; если подходит один корень, он выбирается сразу);
   - позиции без категории — все ветки; доставка и ошибка всего заказа — ветки без категорий сайта.
5. Этап предлагается из списка листа для типа товара: роллы — «Этапы ошибки роллы», пицца — «пицца», напитки и допы — «напитки / допы». Для доставки, заказа и пустого списка — объединение трёх списков; если и оно пустое, этап не нужен. Рядом с этапом — подсказка «i» с описанием.
6. Решение выбирается из решений листа; если их нет, поле не показывается. Для позиций с количеством больше 1 указывается количество.
7. Фото: до 5 на ошибку, JPEG/PNG/WebP до 10 МБ; загружаются сразу при выборе, до сохранения их можно убрать. Если у листа отмечено «Картинка», без фото жалобу сохранить нельзя.
8. Каждая новая регистрация получает свой `client_request_id`; повтор того же запроса не создаёт дубль.

## Варианты решения жалоб

Вкладка показывает и редактирует то же дерево категорий, что и верхняя таблица /option_to_win: название, порядок, родительский раздел (при создании), категории сайта (у корня, потомки наследуют), решения, этапы для роллов, пиццы и напитков/допов, обязательность фото и активность. Удалить можно только вариант без вложенных элементов. Уже зарегистрированные жалобы хранят названия на момент регистрации.

## Workflow

Источник регистрации определяет backend: `cafe` — у сотрудника есть `cafe_decision` и нет `send_to_cafe`/`resolve`, иначе `contact_center`. КК начинает со статуса `registered`, кафе — с `accepted_by_cafe`.

| Статус | Команды |
| --- | --- |
| `registered` | `send_to_cafe`, `resolve`, `cancel` |
| `sent_to_cafe` | `accept`, `return_to_cc`, `cancel` |
| `accepted_by_cafe` | `resolve`, `return_to_cc`, `cancel` |
| `resolved`, `cancelled` | нет |

Статуса `draft` и команды `submit` больше нет. При завершении рассмотрения решение каждой ошибки выбирается из её `solution_ids` (решение регистрации подставляется); если список пуст, поле не показывается и решение регистрации сохраняется. После каждой команды frontend показывает возвращённую деталь со следующими `available_commands`.

## Снятие ошибки

Ошибку можно снять в любом статусе, кроме `cancelled`, при праве `remove_error` и `can_remove`. Комментарий обязателен (до 1000 символов). Снятая ошибка остаётся в жалобе с отметкой (кто, когда, комментарий), не учитывается в суммах и количестве ошибок и не требует решения при завершении. Жалобы со снятыми ошибками выделены в журнале цветом и легендой.

## Инварианты

- Жалоба принадлежит заказу и кафе.
- Ошибка заказа не принадлежит блюду.
- Сервер проверяет кафе, лист дерева и его соответствие позиции, этап по типу товара, решение листа, обязательное фото, количество и переход.
- Ошибка хранит лист, корень, полный путь и снимки названий: корень — «Категория проблемы», остальной путь — «Проблема». Правки дерева не меняют старые жалобы.
- Пока жалоба у кафе (`sent_to_cafe`, `accepted_by_cafe`), сумма изменения скрыта на сервере.
