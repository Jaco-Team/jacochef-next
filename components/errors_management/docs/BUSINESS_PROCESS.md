# Бизнес-процесс

## Регистрация

1. Сотрудник выбирает город и кафе (или «Все точки в городе») и находит заказ: период по умолчанию — сегодня, есть фильтр по времени суток. Номер заказа из одних цифр ищется точно и без периода; любой другой поиск идёт в пределах периода.
2. Регистрация получает состав: блюда, допы, приборы, доставка.
3. Для позиции добавляется любое число ошибок; ошибки заказа добавляются отдельно. Для позиций с количеством больше 1 указывается `quantity` (1…количество позиции).
4. Выбираются категория, тип, ошибка, продукт из состава при необходимости, этап (с описанием в подсказке «i»), суммы, комментарий и решение. Смена категории, типа или ошибки сбрасывает этап и продукт.
5. Каждая новая регистрация получает свой `client_request_id`; повтор того же запроса не создаёт дубль.

## Workflow

Источник регистрации определяет backend: `cafe` — у сотрудника есть `cafe_decision` и нет `send_to_cafe`/`resolve`, иначе `contact_center`. КК начинает со статуса `registered`, кафе — с `accepted_by_cafe`.

| Статус | Команды |
| --- | --- |
| `registered` | `send_to_cafe`, `resolve`, `cancel` |
| `sent_to_cafe` | `accept`, `return_to_cc`, `cancel` |
| `accepted_by_cafe` | `resolve`, `return_to_cc`, `cancel` |
| `resolved`, `cancelled` | нет |

Статуса `draft` и команды `submit` больше нет. После каждой команды frontend показывает возвращённую деталь со следующими `available_commands`.

## Снятие ошибки

Ошибку можно снять в любом статусе, кроме `cancelled`, при праве `remove_error` и `can_remove`. Комментарий обязателен (до 1000 символов). Снятая ошибка остаётся в жалобе с отметкой (кто, когда, комментарий), не учитывается в суммах и количестве ошибок и не требует решения при завершении. Жалобы со снятыми ошибками выделены в журнале цветом и легендой.

## Настройки каталога

Общий вариант висит только под общим родителем, вариант кафе — под общим или своим. В редакторе предлагаются только такие родители и только активные этапы этой области. «Запрашивать продукт из состава» доступно лишь для ошибок раздела «Блюдо».

## Инварианты

- Жалоба принадлежит заказу и кафе.
- Ошибка заказа не принадлежит блюду.
- Сервер проверяет кафе, каталог, этап, позицию, количество и переход.
- Пока жалоба у кафе (`sent_to_cafe`, `accepted_by_cafe`), сумма изменения скрыта на сервере.
