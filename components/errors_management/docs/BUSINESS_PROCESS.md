# Бизнес-процесс

## Регистрация

1. Сотрудник выбирает город и кафе (или «Все точки в городе») и находит заказ: период по умолчанию — сегодня, есть фильтр по времени суток. Номер заказа из одних цифр ищется точно и без периода; любой другой поиск идёт в пределах периода.
2. В форме регистрации одинаковые блюда заказа собраны в одну позицию (`dish:<item_id>`) с отметкой «× N». Отдельной строкой идёт «Весь заказ» для ошибок без позиции.
3. На позицию добавляется любое число ошибок. Карточка ошибки:
   - **Проблема** — один список с поиском из листьев дерева /option_to_win, подходящих позиции, сгруппированных по «Категория · Подраздел» (у глубоких веток средняя часть пути через « / »); листья с обязательным фото отмечены «нужно фото». Поиск фильтрует варианты только по названию проблемы: по части слова, без учёта регистра и «ё»; названия категории и подраздела в поиске не участвуют. Подбор: позиция с категорией сайта — ветки с этой категорией; позиция без категории — все ветки; доставка и весь заказ — ветки без категорий сайта. При добавлении ошибки список открывается сразу.
   - **Этап** — кнопки-варианты из списка листа для типа товара (роллы, пицца, напитки/допы; для доставки, заказа и пустого списка — объединение). Показывается, только если этапы есть; единственный вариант выбирается сам. Описания — только в подсказке «i».
   - **Решение** — кнопки из решений листа, необязательно при регистрации; повторное нажатие снимает выбор.
   - **Сколько с ошибкой** — «− n из N +», только если в позиции больше одной штуки.
   - **Фото** — «+ Фото», миниатюры с удалением; до 5 фото JPEG/PNG/WebP до 10 МБ; при обязательном фото — «Для этой проблемы нужно фото».
   - **Комментарий** — по ссылке «+ Комментарий».
   - Внизу карточки — что ещё нужно («Осталось: выберите проблему, выберите этап, добавьте фото»); заполненная карточка выделяется зелёной рамкой.
4. Кнопка «Зарегистрировать жалобу · N ошибок» доступна, когда заполнены все карточки. Каждая регистрация получает свой `client_request_id`.

Продукт из состава и суммы ошибок в форме больше не запрашиваются; поля в БД остаются.

## Варианты решения жалоб

Вкладка показывает и редактирует то же дерево категорий, что и верхняя таблица /option_to_win: название, порядок, родительский раздел (при создании), категории сайта (у корня, потомки наследуют), решения, этапы для роллов, пиццы и напитков/допов, обязательность фото и активность. Удалить можно только вариант без вложенных элементов. Уже зарегистрированные жалобы хранят названия на момент регистрации.

## Workflow

Источник регистрации определяет backend: `cafe` — у сотрудника есть `cafe_decision` и нет `send_to_cafe`/`resolve`, иначе `contact_center`. КК начинает со статуса `registered`, кафе — с `accepted_by_cafe`.

| Статус | Команды |
| --- | --- |
| `registered` | `send_to_cafe`, `resolve`, `cancel` |
| `sent_to_cafe` | `accept`, `return_to_cc`, `cancel` |
| `accepted_by_cafe` | `resolve`, `return_to_cc`, `cancel` |
| `resolved`, `cancelled` | нет |

Статуса `draft` и команды `submit` больше нет. При завершении рассмотрения решение каждой ошибки выбирается кнопками из её `solution_ids` (решение регистрации подставляется, его можно сменить); если список пуст, выбор не показывается и решение регистрации сохраняется. Сумма изменения не запрашивается. После каждой команды frontend показывает возвращённую деталь со следующими `available_commands`.

## Снятие ошибки

Ошибку можно снять в любом статусе, кроме `cancelled`, при праве `remove_error` и `can_remove`. Комментарий обязателен (до 1000 символов). Снятая ошибка остаётся в жалобе с отметкой (кто, когда, комментарий), не учитывается в суммах и количестве ошибок и не требует решения при завершении. Жалобы со снятыми ошибками выделены в журнале цветом и легендой.

## Инварианты

- Жалоба принадлежит заказу и кафе.
- Ошибка заказа не принадлежит блюду.
- Сервер проверяет кафе, лист дерева и его соответствие позиции, этап по типу товара, решение листа, обязательное фото, количество и переход.
- Ошибка хранит лист, корень, полный путь и снимки названий: корень — «Категория проблемы», остальной путь — «Проблема». Правки дерева не меняют старые жалобы.
- Суммы ошибок и изменения не показываются в журнале, детали и диалогах (решение пользователя); поля в БД сохраняются.
