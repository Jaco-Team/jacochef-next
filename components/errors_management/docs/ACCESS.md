# Доступ

Права задаются параметрами модуля 221 в `appointment_group`; роли собираются администраторами из этих прав. Frontend не вычисляет права из `acces` и не использует `app_type`: всё берётся из `get_all.permissions`, который считает backend.

| Право | Что открывает во frontend |
| --- | --- |
| `journal` | вкладка «Журнал жалоб» |
| `registration` | вкладка «Регистрация» и кнопка «Перейти к регистрации» |
| `statistics` | вкладка «Статистика» |
| `settings` | вкладка «Варианты решения жалоб» (дерево категорий /option_to_win); `settings_edit` — изменение дерева |
| `send_to_cafe` | команда «Отправить в кафе» |
| `resolve` | «Завершить рассмотрение» в статусе `registered` |
| `cafe_decision` | «Принять в работу», «Завершить рассмотрение» (после принятия), «Вернуть в контакт-центр» |
| `cancel` | «Отменить жалобу» |
| `remove_error` | «Снять ошибку» (дополнительно нужен `can_remove` у ошибки) |
| `tel` | телефон клиента в списке заказов, карточках, фильтре и модалке заказа |

Команда показывается, только если она есть в `available_commands` и у пользователя есть соответствующее право. Без прав на вкладки показывается пустое состояние «Нет доступных разделов». Без `permissions` в ответе все права считаются выключенными.

Backend дополнительно проверяет доступ к кафе для каждой v2-операции и загрузки фото. `add_cat`, `update_cat`, `set_active_cat` и `delete_cat` модуля требуют `settings_edit`; без него вкладка открывается только для просмотра.
