Дата последней направленной проверки: 02.10.2026.

## Покрытие

- Изображения: общий allowlist JPG/JPEG, PNG, WebP, GIF, BMP и лимит 10 МБ подключены к трём module-local upload-контролам. В активном legacy editor браузером проверены отклонение SVG и превышения размера, удаление ошибочного файла, замена PNG на GIF без накопления файлов, декодированный локальный preview (`complete` и `naturalWidth > 0`) и отсутствие устаревшего сообщения об ошибке загрузки после rejected selection. API upload отправляется только после сохранения карточки. Alternate editor и view проверены синтаксически и через общий helper, отдельно браузером не открывались.
- Connected input/popup: старая и новая категории, маркировка, этапы состава, номенклатура, базовая единица и складские связи. Проверены ширина, общая граница и сопряжённые углы при открытии вниз/вверх, поиск, выбор, очистка и перенос пяти длинных tags / нескольких allergens без clipping. Warehouse category/unit сохраняют HTML `required`.
- Свободный состав полуфабриката: canonical textarea не менее трёх строк, точное сохранение пробелов, запятых, повторов и переносов. У рецепта поле скрыто. Прежние CSV-only проверки production заменены; остальные CSV-контролы модуля не менялись.
- Должности в кафе: «Не требуется» исключает обычные должности и наоборот; проверены последующий выбор, удаление chip, очистка, старое смешанное сочетание без изменений при открытии/сохранении, прежний `apps: [{id}]`, read-only права. Правило не зависит от числового sentinel ID и учитывает регистр/пробелы в названии option.

- Четыре рабочие вкладки: производство, товары склада, товары сайта, единицы измерения; VK action отсутствует.
- Warehouse: фильтры, создание, повторное открытие созданной записи и редактирование через canonical `items/*`; отдельные права просмотра/редактирования без других разделов.
- Warehouse tree: фактические 2/3 уровня `parent_id`, короткие заголовки и полный путь autocomplete, агрегированные counts без двойного учёта и таблица собственных товаров родителя. Разные ID с одинаковым именем, null/0, отсутствующий справочник/родитель, self-link, циклы и пустые служебные предки не теряют товары. Проверены collapsed default, раскрытие всех/пути фильтра, сохранение ручного collapse при refresh, независимые страницы и 25/50/100 строк внутри категории, поиск, статус, clear/all с точным `category_key`, история и блокировка удаления. Горизонтальная прокрутка остаётся внутри таблиц на mobile.
- Slash-URL каждой вкладки: deep link, «Обновить», reload, back/forward, сохранение других query-параметров, fallback для неизвестного или запрещённого раздела.
- Совместимость старого `?tab`: один replace на slash-путь без `tab`; путь приоритетнее старого query. Sibling-навигация не повторяет `get_all`.
- До готовности bootstrap вкладки не запрашивают свои API; прямой warehouse URL отправляет только `get_all` и `items/list`, без production/site/units list. Код вкладок загружается по требованию.
- Production-таблица: все четыре сочетания активности/ревизии (включая строковые флаги), read-only иконки 24px в цветах success/danger, девять колонок, отсутствие checkbox и запросов при клике по индикаторам. Архив, запланированная/новая версия и два сотрудника сохранены в доступных описаниях. Срок годности отсутствует только в таблице; проверены прежнее значение и сохранение `shelf_life` вместе с изменением ревизии в редакторе.
- Текущие и исторические вложенные связи рецепта блокируют кнопку удаления; запрещённый delete-запрос не отправляется.
- История: периоды, сравнение состава, отмена будущей версии. Исправлено зависание loading после записи загруженных snapshots.
- Существующие CRUD, состав, категории, теги, изображения, архив и матрица прав; запрет удаления используемой единицы.
- Единицы: responsive Dialog/bottom sheet, поля 44px с радиусом 12px, поиск и одиночный выбор базовой единицы, смешанные строковые/числовые ID, точный `con_id` 1/0 и сохранённые количества. «Без привязки», отмена с восстановлением draft, закрытие крестиком, использования с проверенным отступом 16px от поля и create/edit/view/delete права. Полный и отфильтрованный popup не выходят за viewport на обеих ширинах.
- Действия окна единиц: «Отмена» красная слева, «Сохранить» зелёная справа; проверены реальные цвета и положение по краям footer на обеих ширинах. Недоступное сохранение остаётся серым.
- Аудит единиц: создание и изменение с разными авторами, порядок новых записей сверху, значения до/после и названия базовых единиц на момент операции, включая прежнее имя собственной базовой единицы при одновременном переименовании и смене привязки. `units_view` открывает историю в read-only окне без save; `null` / пустая история старых единиц не создаёт фиктивного автора. Явная ошибка и повторная загрузка, disabled fields/save на время загрузки, защита от позднего ответа после закрытия и открытия другой записи.
- Desktop/mobile отсутствие горизонтального переполнения страницы, прокрутка таблиц/вкладок внутри их контейнеров. Устранено 2px переполнение карточки единиц на мобильной ширине.

Mocks приведены к текущим payload-ам: `items/save_*` возвращает `item_id` / `history_id`, detail production содержит expanded snapshots; неизвестный endpoint больше не отвечает фиктивным успехом. Данные `E2E_SKLAD_` изолированы для каждого теста.

## Запуск

- Стандартный запуск: `npm run test:e2e:sklad`.
- Последний прогон: `E2E_BASE_URL=http://localhost:3000` на существующем Docker frontend с `reuseExistingServer`; второй host `next dev` не запускался. Использован `PLAYWRIGHT_EXECUTABLE_PATH` установленного Google Chrome.
- Перед прогоном Docker frontend перезапущен после завершения source edits. Одновременные Docker/host dev server с общим `.next` приводили к Fast Refresh reload loop и ENOENT; нельзя писать dev output двумя серверами одновременно. Глобальное поведение приложения не менялось.

## Артефакты и ограничения

Текущие warehouse-скриншоты: `warehouse-tree-nesting.png` в `output/playwright/warehouse-nesting-visual/`, `warehouse-category-search.png` и `warehouse-filtered-tree.png` в `output/playwright/warehouse-tree-final/`, на desktop/mobile. Отдельные output-директории сохраняют финальные артефакты направленных прогонов. HTML-отчёт: `playwright-report/sklad-items/`. При ошибке сохраняются screenshot, video и trace. Артефакты не добавляются в Git.

- Браузерные тесты используют изолированный API mock, а не рабочую БД; реальные CRUD и Object Storage upload не запускались.
- Mock-прогон не измеряет скорость рабочей БД/API; время cold/warm Docker compilation/HTTP исследуется отдельно.
- Mobile — Chromium-эмуляция, не проверка Safari или физического iPhone.
- Geometry-проверки выполнены для полностью видимого поля. При автоматическом минимальном scroll к частично скрытой за footer номенклатуре на mobile наблюдалось перекрытие popup на 21px по вертикали; после центрирования поля соединение корректно. Общий scroll/Popper runtime ради этого случая не менялся.
- Production-сборка, lint и форматирование в этом изменении не запускались.
- На production ничего не развёртывалось и бизнес-данные не менялись.
