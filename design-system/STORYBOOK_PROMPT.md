# Storybook-first промпт для UI-задач Chef

При любой UI-задаче в `jacochef-next` сначала проверь Storybook:

- открой существующую story для похожего паттерна;
- используй ее как внутренний контракт по токенам, состояниям, плотности и responsive-поведению;
- используй `design-system/shared/ui` как канонический слой переиспользуемых UI-компонентов;
- публичные компоненты дизайн-системы называй `Jaco*`, чтобы не конфликтовать с MUI и legacy `My*`;
- для нового модуля и нового reusable UI запрещено добавлять import из legacy `ui/*` или `ui/My*`: используй существующий `Jaco*` компонент либо сначала создай автономный `Jaco*` + story;
- legacy `ui/*` остается рабочим слоем для уже существующих модулей. Не делай массовый rewire и не удаляй legacy-компоненты вне явно поставленной задачи;
- для task-affected файлов используй актуальные API MUI и мигрируй найденные deprecated MUI-паттерны по ходу задачи;
- если нужный reusable-паттерн есть только в legacy `ui/My*`, пересоздай его как автономный `Jaco*` компонент в `design-system/shared/ui`, выровняй под текущий Chef UI style и добавь/расшири story;
- используй `design-system/shared/tokens` как источник дизайн-токенов;
- если нужного переиспользуемого паттерна нет, сначала добавь или расширь story рядом с `shared/ui`, затем применяй паттерн в модуле;
- сложные составные компоненты выноси в `design-system/widgets` только после того, как базовые shared UI-компоненты уже storyfied;
- Figma используй как внешний эталон дизайна, но реализацию сверяй со Storybook и текущей MUI-темой;
- не вводи новые цвета, радиусы, размеры контролов и modal/sheet shell без обновления дизайн-системной story.
- reusable-компонент считается готовым только после story с normal state и всеми актуальными variant/state сценариями.
